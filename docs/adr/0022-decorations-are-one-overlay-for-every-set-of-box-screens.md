# Decorations are one overlay for every set of box screens

On 2026-11-04 Michael asked for holiday themes the App writes to the box: background, colours, sound and a cartoon figure, starting with Thanksgiving and Christmas. The figure and the sound are a Character, and the holiday Characters Tom and Pip shipped that way (#231). What is left is the rest of the screen. The box already has two sets of box screens (ADR-0021), so a holiday look drawn per set would be designed, built and tested twice, and again for every set we add.

So a decoration is a third thing beside the Character and the box screens, and it uses only what doesn't depend on the layout:

- **Kinds.** Things that fall or drift over the whole screen (snow, leaves) things that hang along its top edge (strings of lights), and things that grow from its bottom corners (pine boughs, a small tree). Nothing that sits at a place a layout gives meaning to: no hats on the buddy, no new backgrounds, no recoloured cards.
- **One drawing for every set of box screens.** The box draws the decoration over the finished 320×240 frame, whichever set drew it, before the night dimming, the menu and the tap outline (`decoration.rs`). Both sets render a full frame and flush it whole (`canvas.rs`, `lcd.rs`), so there is one place to add it. A new set of box screens gets every decoration for free.
- **It never hides what the screen means.** It leaves the top 4 rows alone, where both sets draw the state colour (4 rows on the robot screens, 3 on korekore). It doesn't use the state colours (ready blue, working orange, needs input yellow, done green, failed red) as a main colour, since korekore fills the whole screen with some of them: Christmas lights are warm white and gold with every fourth bulb pink or violet, not red and green bulbs, and the pine is dark pine greens far from the done green. A flake, leaf, acorn or bulb that would touch anything but plain ground (text, an edge, an icon) isn't drawn in that frame, so it seems to pass behind it and text stays whole. The pine is drawn a pixel at a time, only on its corner's ground colour and a pixel clear of anything else, so text, cards and key caps sit on top of it with a pixel of ground around them, and it never fills the inside of a card. Both look at the pixels, not at either layout. While the box needs input, it stops moving, so the only motion on the screen is the buddy asking.
- **In the firmware, picked by a command.** Like the box screens, each decoration is compiled in and switched over the link, and the box keeps the choice across restarts. Off is the default. Turning one on doesn't write the Character pack or flash anything.
- **Named for a holiday, but not tied to a Character or a date.** Pip with no Christmas decoration and the robot with one are both fine. The App doesn't turn a decoration on by the calendar; the user picks it, as with a Character.

## Considered options

- **Holiday backgrounds and colours per set of box screens.** Rejected: twice the design and the pixel tests for each holiday, and a new set of box screens would start with none.
- **Decorations carried in the Character pack.** Rejected: the pack is 2 MB and mostly audio, a decoration would then change with the Character, and the firmware would have to run drawing data it can't check at build time.
- **Drawing the decoration under the screens, as a background.** Rejected: both sets fill the whole frame with their own ground first, so a background would need changes in each set, which is what this ADR avoids.
- **Turning a decoration on by date or region.** Not now: a box that changes on its own is a surprise, and holidays differ by country. It can come later as an App setting that suggests one.

## Consequences

- The firmware gets a decoration step after each set's frame, a `device.decoration` command and a `DECORATION` line, the way `device.screens` works (docs/protocol.md). The settings record has no free word, so the decoration takes the second byte of the screens word; firmware from before it reads a decorated korekore record as the robot's, which only matters after a rollback. The robot and korekore pixels stay the same with the decoration off. `cargo run -p vibebuddy-firmware-core --example decoration_preview -- <dir>` draws each decoration on both sets.
- A moving decoration redraws the frame every 150 ms between the screens' own frames, without speeding up the buddy's animation. The rate is checked on the box. It holds still while the menu is up, while the box needs input, and while the screen is dimmed for the night.
- The Mac app and the Linux app both get a decoration strip on the Character page, right under the volume so a long list of Characters doesn't push it out of sight: one preview, playing frames the firmware itself drew (`tools/decoration-previews.sh` into `decorations/`, so the apps never redraw a decoration of their own), and a button for each decoration. It is off while the box is away or runs firmware that doesn't report a decoration, with zh-Hans strings on both sides. It was first on the Device page, beside the box screens; on 2026-11-05 it moved, since people look for a holiday look where they pick the Character.
- The first decorations are Thanksgiving (falling autumn leaves with an acorn here and there, for 2026-11-26) and Christmas (strings of lights hanging in swags across the top, pine boughs with baubles in the bottom left corner, a small tree with a star in the bottom right, and falling snow). Both ship in one firmware release and one App release about a week before Thanksgiving, and that App release also carries Tom and Pip.
- On 2026-11-06, before any of it shipped, the three decorations Leaves, Snow and Lights became these two, one for each holiday: people pick a holiday, not an effect, and lights alone were for December only. The Christmas one first had a pine garland with lights round the edge of the screen. Along the top it sat right against the state colour and read as part of it, and down the sides it broke wherever a screen's content came near the edge. So the lights now hang in swags under the state colour, and the pine is in the bottom corners, where the screens have the most room. The tree is drawn on every screen, with text on top of it, rather than only where it has room: a decoration that comes and goes from one screen to the next looked less like one design. Everything is drawn before the snow, so a flake falls behind it. Thanksgiving got acorns rather than pumpkins: acorns fall, and a pumpkin's orange is too near the working orange. Snow on its own for the rest of the winter is gone for now. Holidays differ by country: Thanksgiving means little outside the US and Canada, so other holidays, such as Lunar New Year, come as decorations of their own. The settings record keeps codes 1 and 2 for the two; 3, which only test boxes stored, reads as off.
