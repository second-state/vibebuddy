# 小灯灵：AgentBeacon 的实体宠物

## 产品定义

小灯灵不是 Codex 宠物的复制品，而是 AgentBeacon 的原创像素角色。Codex、其他本地 Agent、训练任务和 CI 都可以驱动同一只宠物。角色动画、表情和声音在盒子上运行；Mac 只发送稀疏的状态事件。

## 状态语言

| 状态 | 画面 | 语音 |
| --- | --- | --- |
| 空闲 | 呼吸、眨眼 | 无 |
| 工作中 | 浮动、`>` 与循环点阵 | 无 |
| 需要确认 | `!?`、橙色强调 | “需要你确认”一次 |
| 完成 | 开心、跳动、绿色 | “任务完成”一次 |
| 失败/阻塞 | X 眼、下沉、红色 | “任务遇到问题”一次 |
| 失联 | 闭眼、画面转灰、`NO LINK` | 无 |

语音是注意力补充，不是持续状态通道；因此工作中和空闲保持安静。

失联与失败不同：失败是任务的结果，失联是小灯灵自己不知道结果。它必须能表达“我不知道”，否则在 daemon 崩溃或 USB 断开后，它会继续用鲜艳的颜色宣称一个早已过时的状态。失联不播报语音，因为拔线通常是用户自己的动作，而真正断线时用户多半不在旁边。

## 空闲屏

空闲是出现频率最高的一屏，因此它不能只有一句固定的话。小灯灵在空闲时做两件事：

- **轮播当日战绩**：完成了几件、被要求确认了几次、累计忙了多久，每 3 秒换一行。
- **偶尔做个小动作**：每 20 秒左右轮流打盹（闭眼加一个飘起来的 `Z`）、左顾右盼、伸个懒腰。

小动作不是装饰。一台一直亮着、一直是同一帧的设备看上去更像卡住了而不是在待命；小灯灵得先证明自己还醒着，`NO LINK` 才有意义。反过来，失联时不轮播也不做小动作：会动的画面看上去像还活着，正好与它要表达的意思相反。

## 页脚：构建标识

页脚显示固件与 Mac 端的构建标识，格式是 `git describe` 加编译时刻，例如 `9b642af 2026-09-14 17:41`。

**比对由设备来做。** 两边一致时只占一行 `BUILD …`；不一致时分成 `FW …` 和 `MAC …` 两行并转为失败色。让人去读两串哈希再自己对比是不可靠的，而不一致本身才是需要被看见的那个信号——语义版本号做不到这件事，两边都写着 `0.1.0`，却可以相差好几天。还没收到心跳时不算不一致，那只是还不知道。

## 多任务卡片

- 最多显示 3 张活动任务卡，最近活动的任务在最上。
- 每张卡右下角显示它在当前状态里待了多久，秒、分、小时逐级收敛成三格字宽。等待确认时这个数字与状态同色点亮，其余情况灰显——这一栏回答的正是「它等了我多久」。
- 卡片顺序表达时间；小灯灵的全局表情表达最需要用户处理的状态。
- 全局优先级为“需要确认 > 工作中”。因此旧任务等待确认时，即使上方出现了更新的工作任务，小灯灵仍显示需要确认。
- V1 只显示项目名和状态。Codex 官方 Hook 不提供 UI 中的自动任务标题；默认不读取 prompt 或 transcript 来猜标题。

这个拆分比简单照搬桌面 UI 更适合小屏：卡片回答“有哪些任务”，宠物回答“我现在最需要你注意什么”。
