# 氛围小助手：Vibe Buddy 的实体宠物

## 产品定义

氛围小助手不是 Codex 宠物的复制品，而是 Vibe Buddy 的原创像素角色。Codex、其他本地 Agent、训练任务和 CI 都可以驱动同一只宠物。角色动画、表情和声音在盒子上运行；Mac 只发送稀疏的状态事件。

## 状态语言

| 状态 | 画面 | 语音 |
| --- | --- | --- |
| 空闲 | 呼吸、眨眼 | 无 |
| 工作中 | 浮动、`>` 与循环点阵 | 无 |
| 需要确认 | `!?`、橙色强调 | “需要你确认”一次 |
| 完成 | 开心、跳动、绿色 | “任务完成”一次 |
| 失败/阻塞 | X 眼、下沉、红色 | “任务遇到问题”一次 |
| 失联 | 闭眼、画面转灰、`NO LINK` | 无 |

语音是注意力补充，不是持续状态通道；因此工作中和空闲保持安静。

失联与失败不同：失败是任务的结果，失联是氛围小助手自己不知道结果。它必须能表达“我不知道”，否则在 daemon 崩溃或 USB 断开后，它会继续用鲜艳的颜色宣称一个早已过时的状态。失联不播报语音，因为拔线通常是用户自己的动作，而真正断线时用户多半不在旁边。

## 空闲屏

空闲是出现频率最高的一屏，因此它不能只有一句固定的话。氛围小助手在空闲时做两件事：

- **轮播当日战绩**：完成了几件、被要求确认了几次、累计忙了多久，每 3 秒换一行。
- **偶尔做个小动作**：每 20 秒左右轮流打盹（闭眼加一个飘起来的 `Z`）、左顾右盼、伸个懒腰。

小动作不是装饰。一台一直亮着、一直是同一帧的设备看上去更像卡住了而不是在待命；氛围小助手得先证明自己还醒着，`NO LINK` 才有意义。反过来，失联时不轮播也不做小动作：会动的画面看上去像还活着，正好与它要表达的意思相反。

## 页脚：构建标识

页脚常驻两行，分别是本机固件和心跳捎来的 Mac 端，格式是 `git describe` 加编译时刻：

```text
FW     9b642af 2026-09-14 17:41
DAEMON 9b642af 2026-09-14 17:43
```

用构建标识而不是语义版本号：两边都写着 `0.1.0`，却可以相差好几天，看不出任何问题。

**只显示，不判断。** 固件要插 USB、停 daemon 才能烧，daemon 改一行源码就重启，两边大部分时间本来就不在同一个 commit 上；把「不一致」当成告警，几天之内就会被彻底无视。真正会出事的是协议能力不匹配——固件多了一个要求而 Mac 端还没有满足它的那一半——那不是 commit 能回答的问题。

信息本身已经够用了：看到 `NO LINK` 时低头看一眼 `DAEMON` 那行是三天前的，诊断就结束了。两行左对齐到同一列，因为逐字比对靠的是对齐，不是颜色。Mac 端太旧、根本不发这个字段时显示 `?`，这本身就是答案。

## 番茄钟徽章

值班不是氛围小助手唯一的模式：K1 可以切到番茄钟（见 [`pomodoro.md`](pomodoro.md)），值班空闲够久它会自己去休闲（见 [`leisure.md`](leisure.md)）。番茄钟在走而用户切回值班时，右上角有一个小徽章 `F 18:21`（专注）或 `B 04:59`（休息），暂停时闪烁。它只占一行小字，不改变氛围小助手的任何表情。

## 多任务卡片

- 最多显示 3 张活动任务卡，最近活动的任务在最上。
- 每张卡右下角显示它在当前状态里待了多久，秒、分、小时逐级收敛成三格字宽。等待确认时这个数字与状态同色点亮，其余情况灰显——这一栏回答的正是「它等了我多久」。
- 卡片顺序表达时间；氛围小助手的全局表情表达最需要用户处理的状态。
- 全局优先级为“需要确认 > 工作中”。因此旧任务等待确认时，即使上方出现了更新的工作任务，氛围小助手仍显示需要确认。
- 卡片第一行是会话名，第二行是状态、项目名和时长。同一个项目下同时跑几件事时，项目名分不开它们；会话名是 Agent 自己起的：Claude App 为每个会话自动生成的标题，Codex 里用户给线程起的名字，其次是线程记录的分支，再其次是工作目录所在的分支。都没有才退回项目名。仍然不读 prompt 或 transcript：这些名字本来就显示在两个 App 的侧栏里。Codex 线程表里的 `title` 列是原始首条消息，不用。
- 设备字库只有大写字母和数字。会话名滤掉画不出的字符后剩不到三个字母数字（典型是中文标题）就当不可用，退回下一个来源。

这个拆分比简单照搬桌面 UI 更适合小屏：卡片回答“有哪些任务”，宠物回答“我现在最需要你注意什么”。
