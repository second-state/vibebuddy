# XGGF working notes

## 2026-11-01: Status font upgraded from hand-drawn 3x5 to petabyt 5x7

- The status labels now draw with a 5-wide, 7-tall font covering all 95 printable ASCII characters, replacing the 31-glyph 3x5 table in `status.c`. The glyphs come from the petabyt "7x5" font (MIT, © 2020 Petabyte) vendored at `fonts/petabyt-5x7/`; `tools/make-xggf-font.py` converts it into the committed `main/font.{h,c}` (7 packed row bytes per glyph, bit 4 the leftmost column, ascending 0x20–0x7E so lookup is a range check and subtraction). The conversion centers each glyph's ink in its cell (petabyt hugs the left edge for `I ! 1 :`), takes the first of the two upstream `-` definitions, and gives the eight characters upstream leaves undefined (`$ & @ [ \ ] ^ |`, none used by any label) petabyt's own solid fallback block, all listed in the generated header. `LICENSE-ASSETS` records the font as third-party under its own license.
- Renderer geometry: six pixels per character from x=13, rows 0–6 with row 7 blank, so the widest labels (`MUTE OFF`, `-12C 58%`) fill all eight available characters and end at column 59; longer strings clip as before. The table is `const` (95×8 bytes of rodata, about +0.6 KB over the old table) and lookup cost is negligible against the 15.9 ms panel transfer.
- New host checks: `tests/font_test.c` (table completeness, pinned shapes, widest-label bounds and determinism through `status_render`) and `tests/preview.c`, which writes all fifteen label scenarios as 1x and 8x PBM files — the host preview PLAN_XGGF_64X8 step 4 calls for. The 8x contact sheet was reviewed: every label is legible, the clock colon and `I` sit centered after the centering rule, and the stylized petabyt `W` still reads as `W` in `WORKING`. The existing panel/status/buttons host tests and the generator's Python unit tests (`tools/test_make_xggf_font.py`, run by the CI tools discovery, including a staleness check that the committed table matches the vendored font) all pass; `status_test.c` needed no changes.
- Verification: the ESP-IDF 5.5.4 C3 build passed and the ELF shows `xggf_font` (0x2f8 bytes) in `.flash.rodata`, so the table costs flash only and RAM is unchanged. Flashed under `DEVICE.lock` and `tests/physical_serial.py` passed (board identity, hello, every state, malformed and oversized input). The linker reports the app partition is 95% full — pre-existing pressure from the audio work, nudged by this table's ~0.6 KB. On-panel legibility at normal viewing distance still needs the user's eyes.
